# ระบบ Agent และบริการควบคุมเครื่องเช่า

สถานะ: ร่างเพื่อให้ผู้ใช้ตรวจแบบ ยังไม่เริ่ม implementation
วันที่: 2026-10-29

## จุดประสงค์และข้อตกลง

ทำให้เว็บ KamenRaiderPlay ควบคุมเครื่องเช่า Windows จริงได้ เริ่มพิสูจน์กับเครื่องลูกหนึ่งเครื่องก่อนขยายหลายเครื่อง

- เครื่องแม่รัน Next.js และบริการควบคุม C#/.NET Windows Service แยก process บนเครื่องเดียวกัน
- เครื่องลูกใช้ C#/.NET Windows Service เป็น Agent; เวอร์ชันแรกใช้ Moonlight/Sunshine
- หมดเวลาสั่งปิด Windows ทันที ไม่มีแจ้งเตือน ไม่มีช่วงผ่อนผัน
- เวลาเช่าอยู่ฝั่งเซิร์ฟเวอร์เป็นหลัก Agent เก็บสำเนาเพื่อบังคับหมดเวลาเมื่อเครือข่ายหลุด
- ใช้ Reboot Restore Rx Pro ที่มีอยู่ คืนสภาพทุกครั้งที่บูต
- เครื่องใหม่ลงทะเบียนอัตโนมัติ ไม่ต้องกรอกรหัส แต่ต้องรอแอดมินตรวจ ตั้งชื่อ ราคา และอนุมัติ
- เครื่องที่อนุมัติแล้วเปิดรับการเช่ารอบใหม่อัตโนมัติหลังบูตและผ่านการตรวจความพร้อม
- ตั้งพอร์ตเริ่มต้นที่ Agent แล้วแก้ข้อมูลภายหลังบนเว็บได้ การแก้ไม่เปลี่ยน Sunshine หรือ Router จริง
- ผู้ใช้ตั้ง Sunshine และ Port Forward เอง ลูกค้าใช้ publicIp:moonlightPort
- Public IP ใช้ค่าเดียวทั้งร้าน ตรวจผ่าน API โดยเครื่องแม่ที่ออกอินเทอร์เน็ตผ่านร้าน

## ทางเลือกที่พิจารณา

Agent C#/.NET เทียบกับ Node.js: ผู้ใช้เลือก C#/.NET เพื่อทำงานเป็น Windows Service โดยตรง แลกกับการดูแลสองภาษาในโครงการ

รวมงานควบคุมใน Next.js เทียบกับแยกบริการ: ผู้ใช้เลือกแยกบริการ C#/.NET บนเครื่องแม่เดียวกัน ทำให้การรีสตาร์ตเว็บไม่ตัดงานควบคุม แลกกับเพิ่มหนึ่ง service ไม่ต้องเพิ่มเครื่องหรือ Docker

## ขอบเขตและสิ่งที่ยังไม่รวม

รวมลงทะเบียน/อนุมัติเครื่อง ตั้งชื่อและราคาต่อชั่วโมง รายงานสถานะ แก้ข้อมูลเครือข่าย WOL ส่ง PIN เริ่ม/ต่อ/สิ้นสุด lease และการกู้สถานะหลังรีสตาร์ต มีหน้าผู้เช่าและหน้าแอดมินเชื่อมข้อมูลจริง

ราคาเป็นข้อมูลเครื่อง ส่วนการหักยอดเงินจริง การคืนเงิน และ payment gateway ต้องมีแบบธุรกรรมแยกก่อนเปิดขายจริง การทดสอบชุดนี้ใช้รายการเช่าทดลองที่แอดมินสร้างให้ผู้ใช้ ไม่ถือว่าการหักเงินพร้อมใช้งาน

Parsec ไม่รวมในเวอร์ชันแรก VNC/noVNC ในร่างเดิมคงเป็นงานแยก ยังไม่รวมในชุด Agent นี้ ไม่สร้างระบบคืนสภาพแทน Reboot Restore Rx Pro และไม่ตั้งพอร์ต Router อัตโนมัติ

ห้ามปล่อยเช่าซ้อนเครื่องเดียว ห้ามประกาศพร้อมจาก heartbeat อย่างเดียว ห้ามเปลี่ยนพอร์ตจริงจากการแก้ metadata และห้ามใช้ browser timer เป็นผู้บังคับหมดเวลา

## ข้อเสนอทางเทคนิคสำหรับผู้พัฒนา

รายละเอียดในส่วนนี้เป็นข้อเสนอ ไม่ใช่ข้อกำหนดที่ผู้ใช้ระบุเอง

### เจ้าของข้อมูลและการสื่อสาร

- Next.js คงระบบ auth/บัญชีเดิม ตรวจ session และ role ก่อนเรียกบริการควบคุม
- บริการควบคุมเป็นผู้เขียนข้อมูลเครื่อง การอนุมัติ ราคา lease และคำสั่งเพียงแห่งเดียว ใช้ SQLite แยกไฟล์จากฐาน auth บนดิสก์เครื่องแม่ เว็บอ่าน/เขียนผ่าน internal API ไม่เขียนตารางเหล่านี้ตรง
- API สำหรับเว็บ bind loopback และตรวจ service credential ไม่เชื่อ user ID ที่มาจาก browser โดยตรง
- Agent เชื่อมออกผ่าน HTTPS ไปยังบริการใน LAN ใช้ polling/heartbeat ทุก 5 วินาทีในรุ่นแรก คำสั่งและผลตอบรับเก็บถาวร ขาด heartbeat 20 วินาทีแสดง unreachable ไม่ตีความว่าปิดเครื่องแล้ว
- แยกสถานะ approval, connectivity, readiness และ allocation ไม่รวมเป็นสถานะเดียว
- Agent รับเฉพาะคำสั่งที่กำหนดไว้ ไม่มี remote shell ทั่วไป

### ลงทะเบียนและข้อมูลเครื่อง

Agent สร้าง machine ID และกุญแจประจำเครื่องตอนติดตั้ง ลงทะเบียน public key อัตโนมัติใน LAN เป็น pending แอดมินอนุมัติ identity นั้นก่อนใช้งานจริง คำขอซ้ำใช้ identity เดิม ไม่จับคู่สิทธิ์ด้วย MAC/IP อย่างเดียว กุญแจถูกจำกัดสิทธิ์ไฟล์ให้ service/admin และบันทึกใน baseline ของเครื่องนั้น ห้าม clone identity ไปหลายเครื่อง

ข้อมูลประกอบด้วย machineId, approvalStatus, displayName, hourlyPriceMinorUnits, localIp, macAddress, moonlightPort, sunshinePort, configRevision, lastSeenAt, bootId, readiness และ agentVersion; อาจแนบ CPU/GPU/RAM เป็นข้อมูลรายงาน

publicIp และเวลาที่ตรวจล่าสุดอยู่ระดับร้าน API ของเครื่องประกอบค่าให้ลูกค้าได้ เครื่องแม่ตั้งค่า broadcast/interface สำหรับ WOL ตาม subnet จริง

Agent ส่งพอร์ตตั้งต้นเฉพาะลงทะเบียนครั้งแรก หลังจากนั้นค่าที่แก้บนเว็บเป็นหลัก ส่ง revision ใหม่ให้ Agent และแสดงสถานะรอรับ/รับแล้ว บูตจาก baseline เก่าต้องดึงค่าล่าสุด ห้ามเขียนทับด้วยค่าที่รายงานเก่า localIp/MAC ให้ Agent รายงานจาก adapter ที่เลือก

sunshinePort หมายถึง management API บน localhost ส่วน moonlightPort หมายถึงพอร์ตภายนอกที่ลูกค้าใช้ การแก้ metadata ไม่รับประกันว่า forward ใช้งานได้ ต้องทดสอบจากนอก LAN หาก API public IP ล้มเหลวเก็บค่าล่าสุดพร้อมสถานะล้าสมัย ไม่เขียนค่าว่างทับ

### วงจรเช่าและคำสั่ง

lease: reserved -> preparing -> active -> ending -> completed หรือ failed บังคับหนึ่ง allocation ต่อเครื่องด้วย transaction/unique constraint

ก่อนเริ่มเช่าจัดสรรเครื่องก่อน ส่ง WOL หากจำเป็น รอ Agent กับ Sunshine พร้อม จากนั้นส่ง lease ที่มี rentalId, revision, expiresAtUtc และ commandId ต้องบันทึกสำเนาลงดิสก์ก่อน ACK จึงเปลี่ยนเป็น active เปิดให้ส่ง PIN และแสดงเวลาเริ่มเช่า ไม่คิดเวลาระหว่างบูต ค่า preparing timeout เสนอ 5 นาที

การต่อเวลาเพิ่ม revision และแสดง pending จน Agent ยืนยัน ถ้าไม่ได้รับ ACK ไม่แสดงสำเร็จ ต้องตรวจสถานะซ้ำก่อนตัดสินว่าไม่สำเร็จเพราะ ACK อาจสูญหาย คำสั่งมี TTL, rentalId, revision และ bootId เมื่อเกี่ยวข้อง เพื่อกันคำสั่งเก่ามาปิดการเช่าใหม่

เก็บ UTC ใช้เวลาเซิร์ฟเวอร์ร่วมกับ monotonic timer ระหว่างรัน การ reconnect ไม่เริ่มนับเวลาใหม่ การรีสตาร์ต service ในบูตเดิมอ่าน lease เดิมได้ การรีบูตเครื่องต้อง reconcile กับเครื่องแม่ใหม่ เนื่องจาก Restore Rx อาจย้อนสำเนาในดิสก์

### หมดเวลาและบูตกลับ

เมื่อถึงเวลา Agent ออกคำสั่ง shutdown ทันทีแบบไม่มี countdown และบังคับปิดแอปที่ขวาง ไม่มีการรอ revoke สำเร็จก่อน shutdown ระยะเวลาที่ Windows ใช้ปิดตัวเป็นข้อจำกัดของระบบปฏิบัติการ ไม่รับประกันว่าไฟดับตรงวินาที

การขาด heartbeat ไม่ยืนยัน shutdown สำเร็จ ให้คง ending/unreachable และห้ามแจกเครื่องให้คนใหม่จนเห็นบูตใหม่พร้อมเงื่อนไขคืนสภาพและตรวจบริการ

Reboot Restore Rx Pro ตั้งคืนสภาพทุกบูต baseline ต้องมี Agent/identity และ Sunshine ที่ไม่มีลูกค้าเก่าจับคู่ พร้อมสภาพ Windows ที่สตรีมได้ ผู้ติดตั้งต้องทดสอบ desktop จริงหลัง cold boot ไม่ถือว่า Windows Service แสดง desktop ได้เอง

เมื่อบูต Agent ปิดกั้นบริการสตรีมของผู้เช่าไว้ก่อน reconcile ถ้าเชื่อมเครื่องแม่ไม่ได้ให้คงไม่พร้อมและไม่เปิดสตรีม ไม่ใช้ lease เก่าจาก baseline เพื่ออนุญาตใช้งาน หาก lease เดิมยังไม่หมดให้กลับเข้า lease เดิมและจับคู่ใหม่ได้ หากหมดแล้วให้จบรอบเดิมและเข้าสู่พร้อมเมื่อสภาพเครื่องผ่านการตรวจ ไม่สั่งปิดซ้ำวนเพราะพบ lease เก่าที่จบแล้ว

การเปิดรับรอบใหม่อัตโนมัติหมายถึงหลังเครื่องถูกเปิดแล้ว ไม่หมายถึงเปิดเครื่องวนเองทุกครั้งที่หมดเวลา ค่าเริ่มต้นเสนอให้ WOL เมื่อแอดมินสั่งหรือมีคำขอจัดสรรที่อนุญาต

รุ่นแรกใช้การตรวจและรับรอง baseline/restore-on-every-boot ตอนติดตั้ง พร้อม bootId ใหม่และ Sunshine ที่ไม่มี pairing ค้างเป็นเงื่อนไขคืนสภาพ ไม่กล่าวอ้างว่า heartbeat พิสูจน์การล้างดิสก์ได้ หากตรวจพบการคืนสภาพผิดปกติให้ not-ready รอตรวจ ไม่ปล่อยเช่า

### Sunshine และเครือข่าย

เว็บตรวจเจ้าของ lease ก่อนรับ PIN ส่งไปยังเครื่องที่จัดสรรเท่านั้น Agent เรียก Sunshine localhost ด้วย credentials ที่เก็บในเครื่อง ไม่ส่ง credential ให้ browser ไม่บันทึก PIN ลง log

ก่อนเริ่มเช่ารอบใหม่ตรวจ/ล้าง pairing ของผู้เช่าเดิม และทดสอบว่าลูกค้าเดิมกลับเข้าไม่ได้ ยึด API Sunshine รุ่นติดตั้งจริงและยืนยันการตัด session ไม่อาศัย unpair เพียงอย่างเดียว เมื่อไม่มี active lease ต้องปิดกั้นการสตรีมและการจับคู่ของลูกค้า

ผู้ใช้ตั้งชุดพอร์ต TCP/UDP ไม่ทับกันและ forward เอง management API ไม่ต้องเปิดอินเทอร์เน็ต ตรวจ public IP/CGNAT และความเข้ากันได้ custom port ของ Moonlight ที่ใช้งานจริงก่อนรับรองเชื่อมต่อภายนอก

## ลำดับส่งมอบที่เสนอ

1. โครงสร้าง Controller/Agent, identity, pending approval, ชื่อ/ราคา และ heartbeat
2. config revision, Public IP และ WOL พร้อมทดสอบเครื่องจริง
3. lease ทดลอง การต่อเวลา การปิดเครื่อง และการกู้สถานะร่วมกับ Restore Rx
4. Sunshine PIN และการแยกสิทธิ์ระหว่างผู้เช่า ทดสอบภายนอก LAN
5. เชื่อมหน้าผู้เช่า/แอดมินและทดสอบครบวงจร ก่อนออกแบบการหักเงินจริงต่อ

## เกณฑ์รับงาน

- เครื่องใหม่ pending ใช้เช่าไม่ได้ จนแอดมินตั้งชื่อ ราคา และอนุมัติ
- รีบูตไม่สร้างเครื่องซ้ำ ไม่ย้อนพอร์ตที่แก้ และไม่สูญเสียการอนุมัติ
- สองคำขอพร้อมกันได้ allocation เพียงหนึ่งรายการ
- WOL หลัง shutdown จริงได้ และไม่แสดง ready ก่อน Sunshine/lease พร้อม
- หมดเวลาปิดทันทีไม่มีเตือน ทั้งขณะเชื่อมต่อปกติและตัดเครื่องแม่ออก
- รีสตาร์ตเว็บไม่หยุด Controller; รีสตาร์ต Agent ไม่เพิ่มเวลาเช่า
- คำสั่งเก่า/ซ้ำและการต่อเวลาที่ ACK สูญหายไม่ปิดผิดรอบหรือแสดงผลสำเร็จผิด
- Restore Rx คืน baseline หลังบูต แล้วดึงค่าล่าสุดก่อนเปิดสิทธิ์
- ผู้เช่าเดิมเข้าเครื่องไม่ได้หลังจบรอบและในรอบใหม่ ผู้เช่าอื่นส่ง PIN แทนไม่ได้
- เครื่องไม่พร้อมหรือไม่ได้เชื่อมเครื่องแม่หลังบูตไม่ถูกปล่อยเช่าอัตโนมัติ
- ทดสอบ Moonlight จากนอก LAN ด้วย publicIp:moonlightPort จริง
