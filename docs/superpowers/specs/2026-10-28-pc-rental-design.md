# ระบบเช่าคอมระยะไกล KamenRider — ร่างแบบระบบ

สถานะ: รอผู้ใช้ตรวจแบบ ยังไม่ได้อนุมัติการเลือกเทคโนโลยีเพิ่มเติม

## ข้อกำหนดที่ยืนยันแล้ว

- เครื่องแม่และเครื่องลูกใช้ Windows อยู่ LAN เดียวกัน
- เครื่องแม่รันเว็บและจัดการเครื่องลูกผ่าน Agent
- หนึ่งเครื่องให้ผู้เช่าได้หนึ่งคนในเวลาเดียวกัน
- ลูกค้าใช้ Moonlight และกรอก PIN บนเว็บ เพื่อส่งไป Sunshine API
- ต้องรองรับ Parsec ด้วย แต่ยังไม่ได้ยืนยันรูปแบบการให้และถอนสิทธิ์
- แอดมินดูจอผ่าน VNC ในหน้าเว็บ
- มี Wake-on-LAN และปิดเครื่องเมื่อหมดเวลาเช่า

## สภาพโปรเจกต์ปัจจุบัน

Next.js App Router, TypeScript, shadcn และ IBM Plex Sans Thai พร้อมใช้งาน
มีแพ็กเกจ TanStack Query, Better Auth, Drizzle และ SQLite แล้ว แต่ยังไม่มีระบบเช่าหรือ Agent

## แนวทางที่เสนอ (ยังไม่ใช่การตัดสินใจของผู้ใช้)

1. แนะนำ Next.js + บริการควบคุม TypeScript แยก process + Agent C#/.NET Windows Service
   ใช้ระบบ Windows Service โดยตรง แต่ต้องดูแลสองภาษา
2. ทางเลือก: Agent TypeScript/Node.js ใช้ภาษาเดียวกับเว็บ แต่ต้องเพิ่มวิธีติดตั้งและดูแล Windows Service

เสนอใช้ SQLite + Drizzle สำหรับเครื่องแม่เดียวในระยะแรก จัดเก็บบนดิสก์เครื่องแม่
ให้บริการควบคุมเป็นผู้เขียนข้อมูลการจัดสรรเครื่องและเวลาเช่าเพียงแห่งเดียว
เว็บส่งคำขอผ่าน API ภายในที่ตรวจสิทธิ์ และไม่เปิดบริการควบคุมให้เรียกโดยไม่มีการยืนยันตัวตน
คง Next.js สำหรับหน้าเว็บและการเข้าสู่ระบบ ใช้ TanStack Query สำหรับข้อมูลที่เปลี่ยนระหว่างใช้งาน

## ขอบเขตแรกที่นำไปทดลองได้

เริ่มทดสอบใน LAN กับเครื่องลูกหนึ่งเครื่อง โดยแอดมินสร้างรายการเช่าทดลองให้บัญชีลูกค้า
รวมลงทะเบียน Agent, สถานะเครื่อง, Wake-on-LAN, PIN Sunshine, noVNC และการหมดเวลา
การรับเงินจริง ราคา และการเปิดบริการจากอินเทอร์เน็ตอยู่ในระยะถัดไป
Parsec ยังคงเป็นข้อกำหนดของผลิตภัณฑ์ แต่ไม่แสดงว่าใช้งานได้จนพิสูจน์การให้สิทธิ์และตัดสิทธิ์จริง

## ส่วนประกอบ

- เว็บ: หน้าเข้าใช้งาน, เครื่องที่เช่า, เวลาเหลือ, ส่ง PIN และหลังบ้านจัดการเครื่อง/รายการเช่า
- บริการควบคุม: จัดสรรเครื่อง, เก็บคำสั่งถาวร, ตรวจเวลา, ส่ง WOL, รับสถานะ Agent และออกสิทธิ์ดูจอ
- Agent: เชื่อมต่อออกไปเครื่องแม่ผ่าน TLS, ยืนยันตัวตนรายเครื่อง, รายงาน heartbeat,
  รับคำสั่งเฉพาะที่อนุญาต และเก็บเวลาหมดอายุในเครื่องลูก
- Sunshine: รับ PIN ผ่าน Agent ที่เรียก API บน localhost; เก็บรหัส Sunshine ฝั่งเครื่องลูก
- VNC: เสนอ UltraVNC Server บนเครื่องลูก และ noVNC ผ่าน gateway บนเครื่องแม่
  ตรวจความเข้ากันได้กับการยืนยันตัวตนและหน้าจอ Windows จริงก่อนเลือกการตั้งค่าถาวร
- ติดตั้ง Agent และ VNC เป็น service; งานแสดงข้อความเตือนบน desktop ใช้ helper ใน user session
  ไม่สมมติว่า service วาด UI บนหน้าจอผู้เช่าได้โดยตรง

## การจัดสรรเครื่องและเวลาเช่า

- เก็บสถานะการเช่าแยกจากสถานะการเชื่อมต่อ/พลังงานเครื่อง
- มี machine allocation หนึ่งรายการต่อเครื่อง บังคับ uniqueness ในฐานข้อมูล
  การจองพร้อมกันต้องมีผู้สำเร็จเพียงคนเดียวด้วย transaction
- วงจร: reserved -> preparing -> active -> ending -> completed; มี failed สำหรับกรณีเตรียมไม่สำเร็จ
- จัดสรรเครื่องก่อนปลุกเครื่อง เริ่มจับเวลาเมื่อ Agent ยืนยันพร้อมและรับ lease แล้ว
  ไม่เริ่มคิดเวลาระหว่างบูต; ค่าเริ่มต้นทดลองให้ preparing timeout หลัง 5 นาที
- ก่อน active ห้ามจับคู่ลูกค้า; machine พร้อมต้องหมายถึง Agent เชื่อมต่อและ Sunshine พร้อม
- คำสั่งระบุ command ID, rental ID, lease revision และอายุคำสั่ง
  Agent ทำซ้ำได้อย่างปลอดภัย และปฏิเสธคำสั่งเก่าของการเช่าก่อนหน้า
- ต่อเวลาได้โดยเพิ่ม revision; หน้าเว็บแสดง pending จน Agent บันทึกและตอบรับเวลาใหม่
  ห้ามยืนยันว่าต่อเวลาสำเร็จขณะ Agent ติดต่อไม่ได้
- เก็บเวลา UTC และแสดงตาม Asia/Bangkok; ระหว่างรันใช้ monotonic elapsed time ช่วยกันนาฬิกาถอย
- เก็บ lease ลงดิสก์ก่อนตอบรับ กู้คืนเมื่อ Agent รีสตาร์ต; หากพิสูจน์เวลา/lease ไม่ได้ให้ปิดสิทธิ์สตรีม
  และรอ reconciliation ไม่เปิดให้ผู้เช่ารอบใหม่ใช้ต่อเอง

## Sunshine และการหมดเวลา

- เว็บรับเฉพาะ PIN และตัวระบุการเช่าที่ตรวจ ownership แล้ว ไม่รับ URL ปลายทางจากลูกค้า
- ลูกค้าเริ่มจับคู่ใน Moonlight ก่อน; Agent เลือก pending pairing ที่เกี่ยวข้องตาม API รุ่นที่ติดตั้ง
  ตรวจ API/schema ของ Sunshine จริงก่อนเขียน adapter
- บันทึก client UUID ที่จับคู่ให้แต่ละ rental; ไม่เพิกถอน client แอดมินหรือของระบบโดยเหมารวม
- เตือนผู้เช่าก่อนหมดเวลา 5 นาทีและ 1 นาที เมื่อระยะเช่าเอื้ออำนวย
- เมื่อหมดเวลา Agent ปิดช่องทางสตรีมของผู้เช่าและเพิกถอน pairing ก่อนสั่งปิด Windows
  การ unpair อย่างเดียวไม่ถือเป็นหลักฐานว่า session ที่กำลังทำงานถูกตัดแล้ว
- จนกว่าจะตรวจสอบการตัด session ของ Sunshine รุ่นจริงได้ ให้ปิดบริการสตรีมเป็น fallback
  เครื่องใหม่จะไม่พร้อมจนระบบยืนยันว่าไม่มีสิทธิ์ค้างจากผู้เช่าก่อนหน้า
- Agent บังคับเวลาหมดอายุได้เมื่อเครื่องแม่/เว็บล่ม ไม่อาศัย browser timer
- ปิดเครื่องแบบปกติก่อน; ข้อเสนอสำหรับการทดลองคือรอ 60 วินาทีแล้ว force shutdown
  ต้องแจ้งนโยบายนี้ก่อนเริ่มเช่า เพราะโปรแกรมที่ยังไม่ได้บันทึกอาจสูญเสียข้อมูล
- การขาด heartbeat หมายถึง unreachable ไม่ใช่หลักฐานว่าเครื่องปิดสำเร็จ
  เครื่องคงถูกกันไว้จนมีหลักฐานหรือการตรวจสอบโดยแอดมิน

## VNC และการเข้าถึง

- noVNC ใช้ WSS ไป gateway; gateway ตรวจ session แอดมินและสิทธิ์เครื่องทุกครั้ง
- token ดูจออายุสั้น ผูกกับบัญชีและเครื่องเป้าหมาย ห้ามให้ลูกค้ากำหนด host/port เอง
- ระยะแรกดูอย่างเดียว บังคับที่ VNC server หรือ gateway ไม่พึ่ง flag ในเบราว์เซอร์อย่างเดียว
- จำกัด VNC และ Sunshine management API ใน LAN และตาม firewall policy
- บันทึกว่าแอดมินคนใดดูเครื่องใดเวลาใด และแจ้งผู้เช่าเรื่องการดูจอเพื่อช่วยเหลือ
- VNC ต้องดู desktop เดียวกับที่ผู้เช่าใช้จริง ทดสอบทั้งตอนไม่มีคน login และระหว่างสตรีม

## Wake-on-LAN และเครือข่าย

- เครื่องแม่เปิดค้างและส่ง magic packet ใน LAN ตาม MAC ที่บันทึกไว้
- กำหนด IP เครื่องลูกให้คงที่ผ่าน DHCP reservation หรือ static IP
- ทดสอบ BIOS, NIC, ไฟเลี้ยง, Fast Startup และ wake หลัง shutdown จริงทีละเครื่อง
- Agent connection, VNC และ Sunshine management อยู่ใน LAN
- การสตรีม Moonlight จากภายนอกต้องออกแบบแยกหลังทราบ public IP/CGNAT และ router
  การจับคู่ PIN ไม่ทำให้ข้าม NAT ได้อัตโนมัติ

## การแยกผู้เช่า

- บัญชี Windows ผู้เช่าไม่มีสิทธิ์ admin; ไม่ให้เข้าถึง credential ของ Agent/Sunshine/VNC
- การปิดเครื่องไม่ล้างบัญชีเกมหรือข้อมูลเดิม ต้องกำหนดวิธี reset profile/image ก่อนให้ลูกค้าจริงผลัดกันใช้
- หลังจบการเช่าให้เข้าขั้นตอนตรวจ/เตรียมเครื่องก่อนปล่อยเช่ารอบใหม่
  ระยะแรกแอดมินตรวจและกดพร้อมใช้งานเอง ไม่อ้างว่ามีระบบล้างข้อมูลอัตโนมัติ

## เกณฑ์ทดสอบ

1. Agent ที่ลงทะเบียนแล้วเท่านั้นปรากฏเป็นเครื่องที่ควบคุมได้; ผู้ไม่มีสิทธิ์สั่งงานไม่ได้
2. คำขอเริ่มเช่าพร้อมกันสองคนได้เครื่องเพียงคนเดียว
3. ผู้เช่าส่ง PIN ให้เครื่องของตนได้และไม่มี credential Sunshine หลุดไปเบราว์เซอร์
4. แอดมินดูจอจริงผ่าน noVNC ได้; ลูกค้าหรือ token ของเครื่องอื่นเปิดไม่ได้
5. หลังหมดเวลา session เดิมถูกตัดและจับคู่เดิมกลับเข้าใหม่ไม่ได้ ก่อนเริ่มผู้เช่ารายใหม่
6. ปิดเว็บ/ตัดการเชื่อมต่อเครื่องแม่แล้ว Agent ยังบังคับหมดเวลาได้
7. ต่อเวลาและคำสั่งเก่าที่มาถึงล่าช้าไม่ทำให้ lease ใหม่ถูกปิดผิดรอบ
8. Agent รีสตาร์ตระหว่างเช่าแล้วกู้คืนเวลาและสิทธิ์อย่างถูกต้อง
9. ปิดเครื่องแล้ว Wake-on-LAN เปิดกลับมาได้จริง

## สิ่งที่ยังต้องยืนยันก่อนเปิดบริการจริง

- แนวทาง Agent C#/.NET เป็นข้อเสนอที่รอผู้ใช้เลือก
- วิธีเข้าถึง Sunshine จากภายนอกตามเครือข่ายจริง
- การให้และถอนสิทธิ์ Parsec รวมถึงบัญชี/ผลิตภัณฑ์ที่รองรับ
- วิธีคืนเครื่องสภาพสะอาดระหว่างผู้เช่า
- ราคา การจ่ายเงิน การคืนเงิน และนโยบายบังคับปิดเครื่อง
